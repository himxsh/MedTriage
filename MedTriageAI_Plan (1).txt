AI-Powered Intelligent Triage & Decision Support System
HackCrux Hackathon — Problem Statement 2 | Detailed Project Plan

1. Project Overview
MedTriage AI is an AI-powered triage assistant that converts unstructured healthcare information — patient intake notes, consultation summaries, and voice recordings — into structured summaries and urgency-based prioritization signals. The system is designed to augment (not replace) clinical judgment by reducing cognitive load and improving workflow efficiency for healthcare providers.

Project Name
MedTriage AI — Intelligent Triage & Decision Support System
Problem Domain
Healthcare AI / Clinical Workflow Optimization
Target Users
ER Staff, Nurses, Physicians, Healthcare Administrators
Core Output
Structured case summaries, urgency classification, workflow dashboard
Approach
Prototype-first, using synthetic/public datasets for responsible AI development


2. Problem Analysis
2.1 The Core Challenge
Healthcare professionals face an explosion of unstructured, fragmented data arriving simultaneously from multiple sources. Manual synthesis of this data leads to:
	•	Documentation burden: clinicians spend 35–55% of their time on administrative tasks
	•	Critical information buried in long, unstructured notes — risk indicators easily missed
	•	Triage delays: slow case prioritization in high-volume environments directly impacts patient outcomes
	•	Communication gaps during handoffs — fragmented notes cause critical information to be overlooked

2.2 Why Existing Solutions Fall Short
	•	Traditional EHR systems require manual, time-intensive data entry
	•	Generic NLP tools lack clinical domain knowledge and nuanced medical entity extraction
	•	Basic keyword search cannot detect urgency or synthesize multi-source context
	•	Most tools are built for documentation, not real-time triage decision support


3. Proposed Solution & Features
3.1 System Vision
MedTriage AI acts as a clinical information assistant at the front of the care workflow. It accepts raw patient information in multiple formats, processes it through AI/NLP pipelines, and surfaces actionable, prioritized information in a clean dashboard.

3.2 Feature 1 — Multi-Modal Input Processing
	•	Accept text inputs: intake forms, clinical notes, referral letters, doctor summaries
	•	Accept audio inputs: voice recordings of patient descriptions or consultations
	•	Automatic Speech-to-Text (STT) transcription pipeline using OpenAI Whisper
	•	Support file uploads (PDF, TXT) and direct text entry via the dashboard

3.3 Feature 2 — Clinical NLP Extraction Engine
	•	Named Entity Recognition (NER): extract symptoms, diagnoses, medications, allergies, timelines, lab values
	•	Relationship extraction: identify symptom duration, onset conditions, and aggravating factors
	•	Medical ontology mapping: map extracted entities to ICD-10 / SNOMED concepts
	•	De-identification layer: remove or mask PII before any AI processing

3.4 Feature 3 — Urgency Classification Model
	•	Multi-class classification: Critical / High / Medium / Low urgency levels
	•	Inspired by established triage scales (ESI, Manchester Triage System)
	•	Model explains its urgency decision by highlighting evidence from the source text
	•	Confidence scoring: flag low-confidence predictions for mandatory human review

3.5 Feature 4 — Structured Summary Generation
	•	LLM-based pipeline condenses raw notes into standardized structured summaries
	•	Output format: Chief Complaint | Key Symptoms | Risk Flags | Recommended Priority
	•	Side-by-side view: original source text vs. generated structured summary for transparency
	•	Export summaries to JSON or PDF for EHR integration

3.6 Feature 5 — Triage Dashboard
	•	Real-time case queue sorted by urgency level with color-coded badges (Red/Orange/Yellow/Green)
	•	Case detail view: structured summary, extracted entities, and full source traceability
	•	Workflow status tracker: Pending Review / In Progress / Completed
	•	Search and filter by urgency, time, keywords, or entity type

3.7 Feature 6 — Responsible AI Safeguards
	•	All predictions include explainability highlights showing which text drove the urgency score
	•	Human-in-the-loop gate: Critical cases require clinician confirmation before actioning
	•	Audit log: track all AI decisions and clinician overrides for accountability
	•	Bias monitoring: evaluate model performance across demographic subgroups in synthetic data


4. Technical Architecture
4.1 System Layers
Layer 1: Input
Accepts text, audio files, and form data. Routes inputs to appropriate preprocessors.
Layer 2: Processing
STT transcription → NLP extraction (NER, summarization) → Urgency classification
Layer 3: Storage
Structured case database with extracted entities, summaries, urgency labels, and audit logs
Layer 4: Presentation
React dashboard: case queue, structured summaries, workflow status, explainability view

4.2 Technology Stack
Backend & AI
	•	Language & Framework: Python with FastAPI for REST API
	•	Speech-to-Text: OpenAI Whisper (open-source, local inference)
	•	Clinical NER: spaCy with scispaCy biomedical models (en_ner_bc5cdr_md) or HuggingFace ClinicalBERT
	•	LLM Summarization: GPT-3.5/4 via API or Meta LLaMA-3 for local/cost-free inference
	•	Urgency Classifier: Fine-tuned BERT classifier or GPT-based few-shot classification
	•	Database: PostgreSQL for case data; Redis for real-time queue management
Frontend
	•	React.js with Tailwind CSS for the triage dashboard
	•	Recharts / Chart.js for workflow statistics and trend visualizations
	•	WebSockets for real-time case queue updates

4.3 End-to-End Pipeline Flow
	•	User submits patient information (text or audio) via the dashboard
	•	If audio: Whisper STT converts speech to raw text transcript
	•	NER model extracts clinical entities: symptoms, duration, medications, risk factors
	•	LLM summarization pipeline generates a structured case summary in standardized format
	•	Urgency classifier assigns a triage level (Critical / High / Medium / Low) with confidence score and text-based explanation
	•	Case is stored and immediately surfaced on the dashboard in the correct priority queue
	•	Clinician reviews, confirms, or overrides the AI triage decision — action logged in audit trail


5. Dataset Strategy
MIMIC-III / MIMIC-IV
Large de-identified ICU clinical notes (PhysioNet). Primary source for NER and summarization.
MTSamples
Publicly available medical transcription samples across 40+ specialties.
n2c2 NLP Challenges
Annotated clinical NLP benchmarks for NER and relation extraction.
Synthea
Open-source synthetic patient generator — realistic test cases with no real data.
GPT-4 Synthetic Data
Generate diverse synthetic patient descriptions across urgency levels for classifier training.

All development uses de-identified or fully synthetic data. MIMIC access requires PhysioNet credentialing — plan for 1–2 week approval lead time and use MTSamples + Synthea as an immediate fallback.

7. Evaluation Metrics
NER Accuracy
F1 score ≥ 0.80 for symptom and risk factor extraction on test set
Urgency Classification
Macro F1 ≥ 0.75; no Critical cases misclassified as Low
Summarization Quality
ROUGE-L ≥ 0.45 on reference summaries
STT Accuracy
Word Error Rate (WER) ≤ 15% on synthetic voice test cases
Dashboard Performance
Case display latency < 3 seconds from submission
Explainability Coverage
100% of predictions include highlighted evidence text


8. Risk Assessment & Mitigations
MIMIC Access Delay
Apply for PhysioNet access early; use MTSamples + Synthea as immediate fallback
LLM API Costs
Use open-source LLaMA-3 for local inference to avoid API costs during development
Model Hallucination
Post-processing validation; flag summaries introducing entities not in source text
Urgency Bias
Balance synthetic training data across urgency levels; monitor per-class metrics
Scope Creep
Maintain strict MVP feature list; defer EHR integration and multilingual support
Demo Reliability
Pre-process 10 test cases as fallback if live inference is slow during demo
