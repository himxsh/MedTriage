MedTriageAI Tech Stack (Readable Format)

1. Intake / Input Layer
- Frontend: React + Tailwind UI
- Clinicians can submit: text, audio, or PDF
- Backend receiver: FastAPI
- Audio handling: triggers local OpenAI Whisper for STT before any downstream processing
- Reference: MedTriageAI_Plan.md (sections 3.2, 4.3)

2. PII Masking / De-identification
- Tools: spaCy / EntityRuler + regex + lookup tables
- Location: inside FastAPI pipeline
- Function: scrubs names, MRNs, dates, and similar identifiers
- Output: replaces identifiers with placeholders before downstream AI processing
- Reference: MedTriageAI_Plan.md (section 3.3)

3. Clinical NER
- Models/tools: spaCy/scispaCy `en_ner_bc5cdr_md` or ClinicalBERT
- Extracted entities: symptoms, medications, labs, diagnoses, timelines, allergies
- Coverage: applied per case
- Reference: MedTriageAI_Plan.md (sections 3.3, 4.2)

4. Relationship Extraction
- Methods: spaCy Matchers, dependency patterns, or a fine-tuned transformer
- Purpose: detect links like onset, duration, aggravators between entities
- Result: converts extracted entities into structured clinical context
- Reference: MedTriageAI_Plan.md (section 3.3)

5. Ontology Mapping
- Methods: spaCy concept-linking or curated ICD-10/SNOMED lookup backed by UMLS
- Purpose: attach standard clinical codes to entities before summarization/classification
- Reference: MedTriageAI_Plan.md (section 3.3)

6. LLM Summarization
- Model/API: Gemini API
- Prompt inputs: cleaned text + extracted relations + ontology codes
- Structured outputs: Chief Complaint, Key Symptoms, Risk Flags, Recommended Priority
- Where shown: case detail view
- References: flowchart.drawio; MedTriageAI_Plan.md (sections 3.5, 4.3)

7. Urgency Classification
- Method: Gemini multi-class prompt
- Classes: Critical / High / Medium / Low
- Additional outputs: confidence + evidence
- Safety gate: low-confidence cases trigger mandatory human review
- References: flowchart.drawio; MedTriageAI_Plan.md (sections 3.4, 4.3)

8. Storage & Queue
- PostgreSQL: stores structured case data + audit logs
- Redis: maintains real-time priority queue for triage dashboard
- Reference: MedTriageAI_Plan.md (section 4.2)

9. Presentation & Controls
- Frontend stack: React + TypeScript + Tailwind
- UI/state components: WebSockets, Zustand/Context, Radix/shadcn primitives, React Query
- Features rendered: dashboard, queue, case detail, decision gate, audit log, exports
- Sync behavior: React Query keeps state in sync
- References: prompt.md; MedTriageAI_Plan.md (section 4.2)
